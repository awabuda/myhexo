> **结论先行**：Hermes 提供两套独立的安全防线。**执行前**：`tools/approval.py` 对终端命令进行正则匹配，命中危险模式则阻塞等待用户审批，支持 CLI 交互输入和 Gateway 按钮审批两种方式。**执行后**：`tools/checkpoint_manager.py` 在每次文件写入前通过影子 git 仓库创建快照，用户随时可回滚到任意历史版本。两者联动：审批系统防止危险命令执行，检查点系统兜底文件误改。

## 10.2 危险模式检测

`DANGEROUS_PATTERNS` 包含 30+ 条正则规则，覆盖常见破坏性操作：

```python
# tools/approval.py
DANGEROUS_PATTERNS = [
    (r'\brm\s+-[^\s]*r',                   "recursive delete"),
    (r'\brm\s+--recursive\b',              "recursive delete (long flag)"),
    (r'\bchmod\s+.*(777|666|o\+.*w)',      "world-writable permissions"),
    (r'\bmkfs\b',                           "format filesystem"),
    (r'\bdd\s+.*if=',                       "disk copy"),
    (r'\bDROP\s+(TABLE|DATABASE)\b',        "SQL DROP"),
    (r'\bDELETE\s+FROM\b(?!.*\bWHERE\b)', "SQL DELETE without WHERE"),
    (r'\bkill\s+-9\s+-1\b',                "kill all processes"),
    (r':\(\)\s*\{.*\}\s*;',                "fork bomb"),
    (r'\b(curl|wget)\b.*\|\s*(ba)?sh\b',   "pipe remote content to shell"),
    # ... 更多规则
]
```

**检测前先规范化**，防止绕过：

```python
def _normalize_command_for_detection(command: str) -> str:
    from tools.ansi_strip import strip_ansi
    command = strip_ansi(command)              # 去除 ANSI 转义序列（防隐藏字符）
    command = command.replace('\x00', '')      # 去除 null 字节
    command = unicodedata.normalize('NFKC', command)  # 全角/半角归一化
    return command
```

## 10.3 CLI 审批交互

```
⚠️  Dangerous command detected: recursive delete
Command: rm -rf /tmp/mydir

[o]nce - allow this one time
[s]ession - allow for this session
[a]lways - add to permanent allowlist
[d]eny - reject this command

Choice [o/s/a/d]: _
```

四种结果：

- **once**：本次执行，下次同类命令仍需审批
- **session**：本次会话内该模式免审批（存内存，重启失效）
- **always**：写入 `~/.hermes/config.yaml` `command_allowlist`，永久免审批
- **deny**：拒绝执行，返回错误给 LLM

## 10.4 Gateway 审批：线程阻塞 + 异步通知

Gateway 场景（Telegram/Discord/Slack）下，审批请求必须跨线程同步：

```python
# 审批流程（tools/approval.py）

# 1. 当前 Agent 线程创建审批条目，阻塞等待
entry = _ApprovalEntry(data={...})
_gateway_queues[session_key].append(entry)
notify_cb({"command": ..., "description": ...})  # 触发向用户发消息（按钮）
entry.event.wait(timeout=300)                      # 阻塞 ← 在这里等用户点击

# 2. 用户点击按钮后，gateway/run.py 调用
resolve_gateway_approval(session_key, choice="once")  # 解除阻塞

# 3. 继续执行或拒绝
result = entry.result  # "once" / "session" / "always" / "deny"
```

**线程安全**：多个并发 Gateway 会话通过 `contextvars.ContextVar` 隔离审批状态，互不干扰。

## 10.5 检查点回滚：影子 git 仓库

`checkpoint_manager.py` 使用独立的影子 git 仓库（不污染用户项目的 `.git`）：

```
~/.hermes/checkpoints/
    └── {sha256(工作目录路径)[:16]}/    ← 影子 git 仓库
          ├── HEAD
          ├── refs/
          ├── objects/
          └── HERMES_WORKDIR            ← 记录对应的原始工作目录路径

GIT_DIR     = ~/.hermes/checkpoints/{hash}/   ← git 操作指向影子仓库
GIT_WORK_TREE = /path/to/user/project/        ← 工作树指向用户目录
```

## 10.6 快照触发时机

```python
# tools/checkpoint_manager.py

def new_turn():
    """每轮对话开始时重置去重集合（防止同一轮重复快照）"""
    _snapshotted_dirs.clear()

def ensure_checkpoint(working_dir: str) -> bool:
    """在 write_file / patch 之前调用，首次触发则创建快照"""
    if working_dir in _snapshotted_dirs:
        return True  # 本轮已快照，跳过
    # git add -A && git commit 到影子仓库
    _snapshotted_dirs.add(working_dir)
    return _create_snapshot(working_dir)
```

**触发条件**：

- `write_file` 写入前
- `patch` 修改前
- 每轮对话仅快照一次（去重），避免 I/O 过多

## 10.7 回滚操作

用户通过 `/rollback` 命令查看和恢复：

```bash
# 列出历史快照
/rollback list
# 输出：
# 1. 2024-01-15 14:23:01  "修改了 app.py 和 utils.py"
# 2. 2024-01-15 14:18:45  "创建了 config.json"

# 回滚到指定快照（git checkout 恢复文件）
/rollback 1
```

## 10.8 两套安全机制对比

| 维度 | 危险命令审批 | 检查点回滚 |
|---|---|---|
| 保护对象 | shell 命令执行 | 文件系统变更 |
| 时机 | 执行前拦截 | 执行后兜底 |
| 触发方式 | 正则模式匹配 | 文件写入时自动 |
| 恢复方式 | 拒绝执行 | git checkout 恢复 |
| 配置项 | `command_allowlist` | `checkpoints: true` |
| 存储位置 | `~/.hermes/config.yaml` | `~/.hermes/checkpoints/` |
